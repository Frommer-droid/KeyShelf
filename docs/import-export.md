# Обмен записями

Во вкладке «Система» доступны импорт и экспорт JSON после открытия хранилища. Файл обмена содержит открытые значения. Мастер-пароль в него не записывается. Экспорт всей базы в KDBX остаётся отдельной функцией резервного копирования.

Импорт сначала проверяет весь документ, затем показывает только число сервисов и записей. Сервисы объединяются по названию без учёта регистра. Записи добавляются одной транзакцией: при ошибке исходное хранилище не меняется. Точные повторы пропускаются, включая повторный импорт того же файла; изменение отметки избранного у существующей записи не создаёт копию. Различные значения при совпавшей метке создают отдельные записи, ничего не перезаписывая.

Экспорт: все сервисы или сервис, выбранный слева. Сохраняются метки, логины, комментарии, избранное, тип записи, проекты, теги и все подписанные поля (включая пустые и поля legacy). Вложения, история KDBX и дерево вложенных групп не экспортируются. Для них нужна зашифрованная резервная копия.

Документ UTF-8 JSON, максимум 10 МиБ и 10 000 записей. Неизвестная версия, неизвестные свойства, повторяющиеся JSON-ключи и некорректная структура отклоняются. Диагностика не содержит значений записей. Пример на вымышленных данных:

```json
{
  "format": "acc-storage-exchange",
  "version": 1,
  "services": [
    {
      "name": "Пример",
      "records": [
        {
          "kind": "api",
          "label": "Рабочий ключ",
          "login": "",
          "comment": "Вымышленные данные",
          "project": "",
          "tags": "",
          "favorite": false,
          "fields": [
            {"label": "API-ключ", "value": "synthetic-key", "secret": true}
          ]
        }
      ]
    }
  ]
}
```

Для `account` поля — `Пароль` и `Секрет 2FA`, оба с `secret: true`; секрет 2FA может быть пустым. Тип `legacy` сохраняет произвольные подписанные поля. Пустые сервисы также передаются.

Необязательный boolean `api_paid` сохраняет отметку платного API. В старых файлах без этого свойства значение считается false. Как и избранное, эта отметка не участвует в проверке дубликатов; повторный импорт не меняет отметку уже существующей записи.

`tools/prepare_text_import.py` — конвертер одного проверенного 74-строчного исходного формата, а не универсальный распознаватель. При изменении структуры или появлении неразобранных строк он прекращает работу. Значения не печатаются. Исключённые владельцем строки не включаются в результат; исходный файл не изменяется. Конвертер не вызывается приложением автоматически.

Тип `other` содержит три защищённых поля `Поле 1`, `Поле 2`, `Поле 3`; метка и комментарий сохраняются отдельно. Пустые значения передаются в JSON, но не показываются в карточке.

У `api`, `account` и `other` после базовых полей могут быть дополнительные защищённые поля с техническими именами `Дополнительное поле 1`, `Дополнительное поле 2` и далее без пропусков и повторов. В редакторе они не имеют видимых подписей. Их значения, включая пустые, сохраняются при обмене. Версия формата остаётся 1; предыдущие версии приложения не поддерживают импорт таких расширенных записей.

Необязательный `field_layout` — список названий видимых полей в порядке редактора. Для аккаунта он также может содержать `Логин`. Удалённые базовые поля сохраняются пустыми и не входят в список; все дополнительные поля входят в него. Имена не повторяются. При отсутствии свойства используется прежний порядок. Порядок учитывается при сравнении повторов импорта; старые версии приложения не поддерживают это свойство.
