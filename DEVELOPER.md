# Разработка KeyShelf

Python 3.12, PySide6, PyKeePass, PyOTP. Все команды выполняются из корня в проектном .venv.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe -m pytest tests -q
.\.venv\Scripts\python.exe -m ruff check .
```

Запуск из исходников — корневой `Запустить.cmd`. Для диагностики: `.\.venv\Scripts\python.exe Acc-storage.py`. settings.json и startup.log локальные, в Git не включаются.

## Архитектура

app/core — модели, ресурсы, настройки, создание QApplication и жизненный цикл. app/services — KDBX, обмен JSON, TOTP, буфер и автозагрузка. app/ui — окно, карточки, редакторы и системный лоток. Файловые операции идут в фоновых задачах; epoch counter отклоняет ответы после блокировки. Выход ждёт завершения операции. Пароли не записываются в настройки и диагностические сообщения.

Vault использует KDBX4 AES-256 с Argon2id: M=67108864, I=3, P=2, V=19. Группы — сервисы, Title/UserName/Notes — метка/логин/комментарий. Пользовательские поля и JSON метаданных защищены внутренним потоком KDBX. Типы api/account/other сохраняются в метаданных; legacy позволяет читать старые произвольные поля. Изменение выполняется через новый файл в том же каталоге, fsync, повторное чтение, проверку fingerprint и os.replace. Предыдущий файл сохраняется как .bak. OS lock sidecar предотвращает конкурирующие операции этого приложения; сторонние программы могут не соблюдать его. Создание без перезаписи использует hard link и требует соответствующую файловую систему.

Формат JSON: [docs/import-export.md](docs/import-export.md). Он содержит открытые значения, ограничен 10 МиБ и 10000 записей. Весь документ валидируется до единой транзакции импорта. История и вложения передаются только через KDBX-копию.

ROOT для исходников — корень проекта, для frozen — каталог exe. resource_path ищет упакованные ресурсы через _MEIPASS. Автозагрузка создаёт управляемый ярлык только в Startup текущего пользователя. Трей сохраняет разблокированную сессию; автоблокировка отсутствует.

## Макси и мини

Это два представления одного MainWindow: `maxi_page` с полным интерфейсом и `MiniPanel` с поиском/результатами. `ViewMode` переключает страницы, применяет минимум окна под текущий масштаб и восстанавливает отдельную геометрию. Кнопка «Мини» доступна после открытия хранилища; возврат «Макси» — действие справа внутри поля поиска. Без запроса мини-панель схлопывается до строки; результаты и раскрытие карточек увеличивают высоту до сохранённого предела, далее используется прокрутка.

В мини поиск всегда глобальный через общую `models.search`, без скрытых фильтров избранного/типов из макси. Секретные значения не индексируются. `AccountCard(compact=True)` оставляет заголовок «сервис · метка», аккордеон и квадратные CopyIconButton для полей и 2FA с подтверждением ✓; действия изменения/удаления/избранного скрыты. Кнопка «Мини» расположена последней справа в верхнем ряду полного интерфейса. Запрос передаётся при переключении представлений и остаётся в памяти при уходе в трей, но не записывается в settings.json.

Настройки `window_mode=maxi|mini`, `mini_pos_x`, `mini_pos_y`, `mini_width`, `mini_height` дополняют прежнюю геометрию макси. `mini_height` хранит предел высоты результатов; автоматическое схлопывание его не перезаписывает. При перезапуске сначала виден экран разблокировки, после открытия хранилища восстанавливается сохранённый режим. Блокировка очищает обе строки поиска и все карточки, сохраняя предпочтение режима. Крестик закрытия при доступном трее скрывает любое представление, включая экран разблокировки; завершение — пункт «Выход». Возврат мини из трея фокусирует поиск с выделением запроса, сохраняя раскрытые карточки. Глобальная горячая клавиша пока не добавлена.

Проверки: `python -m pytest tests/test_mini_mode.py tests/test_tray.py`; живой запуск из проектного `pythonw.exe -m tests.live_mini_smoke <папка-отчёта>` проверяет корневой entrypoint, поиск, аккордеоны, трей, переключение и блокировку на синтетическом KDBX с отдельным временным startup.log.

## Сборка

```powershell
powershell -NoProfile -File Build_Tools/build.ps1
powershell -NoProfile -File Build_Tools/package.ps1
```

build.ps1 использует .venv и минимальный PATH. KeyShelf.spec отклоняет DLL вне проекта, Python и Windows, затем выбирает полный набор MSVC DLL из PySide6. post_build.py повторно проверяет COLLECT-00.toc и идентичность runtime перед подготовкой папки KeyShelf. Новый отчёт сохраняется в ignored `.verification/native-runtime-<версия>.json`; `docs/native-runtime-audit.json` — исторический отчёт выпуска 0.2.1. Лицензии, исходники source и сборочные скрипты включены в поставку вместе с иллюстрацией мини-режима. Пользовательские настройки, логи и хранилища не включаются.

package.ps1 компилирует русский Inno Setup на рабочий стол Windows и копирует переносную папку по настроенному абсолютному пути. Компилятор определяется из `-InnoCompilerPath`, `INNO_SETUP_ISCC`, команды ISCC.exe, стандартных папок или зарегистрированной установки Inno Setup 6. Для копирования доступны `-PortableDirectory` и `KEYSHELF_PORTABLE_DIR`; по умолчанию используется D:\Portable_soft\KeyShelf. `-SkipPortableCopy` компилирует только установщик. Существующая переносная папка обновляется только при наличии RUNTIME_MANIFEST.json и проверенном пути без reparse point; файлы payload перезаписываются, локальные настройки и пользовательские файлы сохраняются. Сборочные скрипты не запускают приложение или установщик.

Установщик выбирает D:\Apps\KeyShelf при наличии D, иначе C:\Apps\KeyShelf. Пользовательские settings.json, логи и KDBX исключены из [Files]; [UninstallDelete] с рекурсивным удалением {app} отсутствует. Удаление управляется штатным журналом установленных файлов Inno Setup. Перед сборкой installer проверяется отсутствие пользовательских данных в корневом payload. AGENT_HANDOFF.md содержит только обезличенное состояние проекта; приватную историю и пути нельзя добавлять ни в Git, ни в source bundle.

Обязательная неинтерактивная проверка фактического exe: `KeyShelf.exe --runtime-smoke-test <абсолютный-путь-отчёта.json>`, с timeout и захватом stdout/stderr. Требуются exit=0, пустой stderr и ok=true. Проверяются Qt, иконка, ресурсы, KDBX create/read/write, AES/Argon2, JSON, TOTP, скрытое окно и завершение. Используется только временное синтетическое хранилище.

Версия хранится в VERSION, version_info.txt и installer.iss; при изменении синхронизировать runtime_smoke. Лицензия проекта GPL-3.0, в том числе используется GPL-3.0-зависимость PyKeePass; общий gate владельца с требованием MIT здесь фиксирует явное проектное исключение, а не основание заменять сторонние лицензии. Требования зависимостей описаны в THIRD_PARTY_NOTICES.md и QT_PYSIDE6_COMPLIANCE.md. Состав установленных пакетов — requirements-lock.txt; для воспроизводимой среды устанавливайте его перед сборкой.

## Дополнительные проверки

`python -m tests.live_smoke` проверяет источник через реальный launcher и создаёт скриншоты с вымышленными данными. `python -m tests.verify_launcher --cmd` проверяет корневой командный файл, иконки и уход в трей, затем принудительно завершает только свой процесс проверки; штатный выход отдельно проверяется live-smoke и test_tray. `python -m tests.verify_compatibility <путь-к-keepassxc-cli.exe>` проверяет совместимость с независимым KeePassXC; CLI не поставляется.

После последней проверки удалять только однозначные временные артефакты по проверенным абсолютным путям внутри репозитория. Сохранять .venv, tests, пользовательские данные, готовые сборки и отчёты релиза.

Фильтры типов: Settings.service_type_filters хранит canonical vault path → service UUID → список api/account/other. Сохранение немедленно при toggled; восстановление с блокировкой сигналов после выбора и обновления сервисов. Избранное остаётся общим. test_service_filters проверяет переключение, переименование, lock/reopen, перезапуск, изоляцию хранилищ и очистку некорректных настроек.
## Масштаб и дополнительные поля (исходники)

`app/services/ui_scale.py` рассчитывает авто-масштаб экрана/DPI и ручную поправку. `app/ui/ui_scale_runtime.py` следит за экранами и применяет QSS и исходные метрики без накопления множителя. Настройки: `ui_scale_mode=auto`, `ui_scale_delta_percent`, диагностический `ui_scale_percent`; старый процент мигрируется. Перенос между мониторами не вызывает явного resize; ручная поправка корректирует обычное окно, развёрнутое сохраняется.

При пересоздании карточек `refresh_cards` применяет метрики текущего масштаба до вставки в видимую панель, чтобы первый показ не предшествовал пересчёту размеров по таймеру. Смена сервиса сбрасывает поиск с блокировкой `textChanged` и обновляет карточки один раз. `itemClicked` нужен только для выхода из поиска повторным кликом по текущему сервису; обычную смену обрабатывает `currentItemChanged`.

Общий `RecordDialog` использует кнопки `+`/`−` слева в нижнем ряду и запоминает FocusIn поля значений при переходе фокуса на кнопки. Вставка идёт ниже активного поля; удаление очищает текст и исключает строку. Без активного поля добавление идёт в конец, удаление недоступно. Тип/метка/комментарий не удаляются. Подписей в боковой колонке нет; стандартные поля обозначены placeholder и accessibleName. Форма прокручивается. `Account.field_layout` сохраняет порядок и отсутствие базовых строк в защищённых метаданных KDBX и необязательном свойстве JSON; значения удалённых базовых полей пустые для совместимости схемы. Дополнительные поля имеют последовательные технические имена. Карточки соблюдают порядок и скрывают пустые значения; быстрое копирование «Другого» берёт первое видимое поле.

При смене типа редактор переносит значения всех видимых строк по порядку в стандартные поля нового типа, а остаток — в дополнительные. Метка и комментарий сохраняются; удалённые строки не участвуют в переносе. Повторные переключения используют текущие значения, отдельных черновиков по типам нет. Проверка секрета 2FA при сохранении аккаунта остаётся обязательной. Неотмеченные кнопки избранного в фильтре и карточках при hover выглядят как отмеченные: закрашенный символ ★, тот же цвет, фон и рамка. Общий FavoriteButton обновляет символ на enter/leave/toggled, сохраняя реальный флаг unchecked при наведении.

Проверка из проектного окружения: `python -m pytest tests/test_ui_scale.py tests/test_extra_fields.py`; для фоновой проверки Qt задайте `QT_QPA_PLATFORM=offscreen`. Настоящий трей требует обычной Windows-сессии.
